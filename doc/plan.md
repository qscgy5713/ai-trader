# 計畫與設計

## 目標
用 Gemini 做交易決策,先在模擬環境驗證它是否比簡單規則更好,再考慮是否值得往實盤發展。

## 範圍
- 已做:合約模式(AI 多空方向,只模擬)、AI 調整網格模式(AI 決定區間 / 格數 / 暫停,網格負責高頻成交)、Gemini 決策(JSON 結構化輸出、嚴格驗證)、風控層、模擬帳戶、即時模擬盤、歷史回放(快取、呼叫上限)、決策日誌與報表、離線規則基準模型。
- 未做:實盤下單(含合約實盤)、多交易對 / 投資組合、新聞或情緒等非價格資料、通知、與規則基準的自動對照報告。

## 設計取捨
- **AI 只建議、風控決定**:模型輸出「目標持倉比例 + 信心 + 理由」,強制規則(停損、單日虧損上限)優先於模型,決策再經信心門檻、持倉上限、最小調整幅度、交易次數過濾。
- **失敗即不交易**:模型輸出不合格、API 錯誤 → HOLD;只有設定錯誤(金鑰、模型名稱)會停止程式。
- **以目標持倉比例表達**:比「買多少」更不容易因模型誤解而下錯量,也方便截斷在上限內。
- **回放不偷看未來**:第 i 根收盤後決策、第 i+1 根開盤成交;但模型可能記得歷史行情,回放結果只能當參考。
- **零依賴**:直接呼叫 Gemini REST `generateContent`(官方仍支援;新的 Interactions API 之後可評估),便於部署與審查。
- **預設模型** `gemini-3.8-flash`(2026-10 官方建議的一般用途模型),可用 `GEMINI_MODEL` 改成更便宜的 `gemini-3.5-flash-lite`。
  每日檢討可另用 `GEMINI_REFLECT_MODEL` / `--reflect-model` 指定較強的模型(例如 `gemini-3.1-pro-preview`),決策維持 Flash 以控制費用。
- **不讓 AI 直接高頻下單**:LLM 每次決策需數秒且有費用,短週期波動又常小於手續費加滑價。改由 AI 低頻判斷行情狀態(盤整 / 趨勢)並調整網格參數,成交交給網格。
- **網格重設只交易差額**:避免每次重設都全部賣出再買回,降低 AI 頻繁調整的成本;另有每日重設上限與「變動太小不重設」。
- **學習用提示詞而不是訓練**:把最近決策的結果與每日檢討出的心得放進提示詞(in-context)。成本低、可隨時關閉比較;
  代價是樣本少時可能學錯,因此心得只當參考,強制風控不受影響。
- **合約先只做模擬、預設保守**:槓桿上限 2 倍、停損以錢包 % 計、單日上限後停機;強平與資金費照實模擬,讓模擬結果不過度樂觀。
  實盤需另外處理 API 權限、倉位級距、插針與斷線風險,確認模擬有效前不做。
- **合約倉位依當日剩餘額度決定**:不是固定槓桿,而是固定「這筆停損最多虧多少」(剩餘額度的一部分),再由最小停損距離推出槓桿上限;
  連續虧損時自動縮小倉位。台幣只是輸入與顯示的換算,帳戶仍以 USDT 計價。

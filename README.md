# ai-trader

用 **Google Gemini** 做交易決策的**模擬交易**系統:每根 K 線收盤後,把技術指標與目前持倉交給 Gemini,
由它建議「目標持倉比例」,再經過程式的**風控層**決定是否真的(模擬)成交。

- **只模擬,不下真單**,也不構成投資建議。
- AI 只提供建議;停損、單日虧損上限、持倉上限、交易次數等規則由程式強制執行。
- 每次決策(含 AI 的理由)都記錄到決策日誌,方便事後檢討。
- 兩種模式:
  - **目標持倉模式**(`once` / `paper` / `replay`):AI 每根 K 線決定要持有多少比例的幣,交易次數少。
  - **AI 調整網格模式**(`grid` / `grid-replay`):AI 每根 K 線決定網格區間與格數(或暫停),
    網格每幾秒撮合一次,負責頻繁的小額低買高賣。AI 費用和目標持倉模式一樣,成交次數多很多。
  - **合約模式**(`futures` / `futures-replay`):USDT 永續合約,AI 決定做多 / 做空 / 空手與槓桿;
    模擬強平、停損、資金費。**只模擬,不下真單。**

## 技術棧
- Python 3.9+,**僅用標準庫**(`urllib`、`json`、`unittest`),無第三方依賴
- AI:Gemini API `generateContent`(REST,JSON 結構化輸出)
- 行情:Binance 公開 API(現貨與 USDT 永續合約,免金鑰)

## 安裝與環境設定

1. 到 [Google AI Studio](https://aistudio.google.com/apikey) 申請 Gemini API 金鑰。
2. 在專案根目錄建立 `.env`(已被 `.gitignore` 排除,不會提交):
   ```bash
   cp .env.example .env
   # 編輯 .env,填入 GEMINI_API_KEY=你的金鑰
   ```
   | 變數 | 預設 | 說明 |
   |---|---|---|
   | `GEMINI_API_KEY` | 必填 | Gemini API 金鑰 |
   | `GEMINI_MODEL` | `gemini-3.8-flash` | 模型名稱;想省錢可改 `gemini-3.5-flash-lite` |
   | `GEMINI_REFLECT_MODEL` | (同 `GEMINI_MODEL`) | 網格 / 合約每日檢討用的模型。檢討一天只呼叫一次,可設成較強的 `gemini-3.1-pro-preview`,決策維持便宜的 Flash;也可用 `--reflect-model` 指定 |
3. 跑測試:
   ```bash
   python3 -m unittest discover -s tests -t .
   ```

**不要把金鑰貼到對話、程式碼或 commit 裡。** 程式只從環境變數 / `.env` 讀取,金鑰放在 HTTP header,不會出現在網址、日誌或錯誤訊息中。

## 使用方式

> 模擬盤(`paper` / `grid` / `futures`)重跑相同指令會自動接續;加 `--reset` 或狀態檔不存在時開新帳戶,
> 舊的決策日誌會自動封存為 `<原檔名>.<時間>.jsonl`,`report` 只會看到目前帳戶。
> `grid` / `futures` 的 `--reset` 預設**沿用 AI 的心得**(帳戶與成績單重來);要連心得一起清除加 `--reset-memory`。

```bash
# 1. 確認金鑰可用:用即時行情問一次 Gemini(只試算,不存檔)
python3 -m aitrader once

# 2. 模擬盤:每根 1h K 線收盤後問 Gemini,兩根之間每分鐘檢查停損
python3 -m aitrader paper

# 3. 歷史回放:最近 500 根 1h K 線,每 4 根問一次,Gemini 最多實際呼叫 100 次
python3 -m aitrader replay --limit 500 --every 4 --max-calls 100

# 4. 用不花錢的規則模型當對照組
python3 -m aitrader replay --model rule --limit 1000 --every 1

# 5. 檢視決策日誌
python3 -m aitrader report journal/paper_BTCUSDT_gemini.jsonl

# 6. AI 調整網格:模擬盤(每 5 秒撮合網格,每小時問 Gemini 是否調整)
python3 -m aitrader grid

# 7. AI 調整網格:歷史回放(先用規則模型看看,不花錢)
python3 -m aitrader grid-replay --model rule --limit 1000 --every 1

# 8. 檢視網格日誌(report 會自動辨識)
python3 -m aitrader report journal/grid_BTCUSDT_gemini.jsonl

# 9. 合約模擬盤(AI 多空,預設槓桿上限 2 倍)
python3 -m aitrader futures

# 10. 合約歷史回放(含歷史資金費;先用規則模型看看)
python3 -m aitrader futures-replay --model rule --limit 1000 --every 1

# 11. 合約用台幣:本金 3 萬元、一天最多虧 1,000 元
python3 -m aitrader futures --currency TWD --cash 30000 --daily-loss-amount 1000
python3 -m aitrader report journal/futures_BTCUSDT_gemini.jsonl --currency TWD
```

### 子指令

| 指令 | 用途 |
|---|---|
| `once` | 用即時行情問一次模型,顯示決策與風控結果。不改任何狀態,適合確認金鑰與模型設定。 |
| `paper` | 模擬盤。狀態存在 `state/`,重跑相同指令自動接續;Ctrl+C 會在安全點存檔結束(再按一次強制結束)。 |
| `replay` | 歷史回放。決策後以**下一根 K 線開盤價**成交(避免偷看未來);每根 K 線都檢查停損。Gemini 回覆會快取在 `cache/`,重跑不重複付費。 |
| `lessons` | 查看 AI 的學習狀況(心得、成績單、待檢討):`lessons state/futures_SOLUSDT_gemini.json`;`--import <日誌>` 從日誌最後一次成功的每日檢討匯入心得;模擬盤執行中也可以,會排入暫存檔,由執行中的程式在下一輪(數十秒內)套用。 |
| `report` | 統計決策日誌:各種決策次數、成交、已實現損益、手續費、被風控擋下的原因、token 用量、最近決策與理由。網格日誌會自動改用網格報表。 |
| `grid` | AI 調整網格的模擬盤,說明見下方「AI 調整網格模式」。 |
| `grid-replay` | AI 調整網格的歷史回放。 |
| `futures` | 合約模擬盤,說明見下方「合約模式」。 |
| `futures-replay` | 合約歷史回放。 |

### 共用參數

| 參數 | 預設 | 說明 |
|---|---|---|
| `--symbol` | `BTCUSDT` | Binance 交易對 |
| `--interval` | `1h` | K 線週期(`paper` 支援 1m/5m/15m/30m/1h/4h/1d) |
| `--model` | `gemini` | `gemini` 或 `rule`(離線規則基準:均線 + RSI,不花錢) |
| `--cash` | 10000 | 模擬資金 |
| `--fee` | 0.001 | 單邊手續費率 |
| `--slippage-bps` | 5 | 滑價(基點,5 = 0.05%) |

### 風控參數

| 參數 | 預設 | 說明 |
|---|---|---|
| `--max-position` | 50 | 持倉上限(占總權益 %)。AI 要求更高會被截斷。 |
| `--min-confidence` | 0.6 | AI 信心低於此值不交易。 |
| `--min-trade` | 5 | 目標與目前持倉差距小於此 % 不交易,避免手續費磨損。 |
| `--stop-loss` | 5 | 持倉虧損達此 % 強制清倉(不問 AI)。 |
| `--take-profit` | 0 | 持倉獲利達此 % 強制清倉;0 = 不啟用。 |
| `--daily-loss-limit` | 3 | 權益較當日(UTC)開始下跌達此 %,清倉並停止交易到隔天。 |
| `--max-trades` | 6 | 每日最多成交筆數。 |

`paper` 接續時,風控參數**以這次啟動的參數為準**(可隨時調整),帳戶與當日統計沿用狀態檔。

### 其他參數
- `paper`:`--check-every`(兩根 K 線之間檢查停損的秒數,預設 60)、`--state`、`--journal`、`--reset`、`--max-steps`(問模型幾次後結束)。
- `replay`:`--limit`(K 線根數,預設 500)、`--every`(每幾根問一次,預設 4)、`--max-calls`(Gemini 實際呼叫上限,預設 100,快取命中不計)、`--cache-dir`、`--journal`。

## AI 調整網格模式

分工:**AI 決定「在哪個區間、切幾格」,網格負責「頻繁小額低買高賣」**。

- 每 `--tick` 秒(預設 5)取一次現價撮合網格:跌破買單價就買,漲過賣單價就賣(穿價才算成交)。
- 每根 `--interval` K 線(預設 1h)收盤後問 AI,AI 回覆以下三種之一:
  - `KEEP`:維持現狀(預設;重設網格要付手續費)。
  - `SET`:以現價為中心重設網格,下緣 `lower_pct`% / 上緣 `upper_pct`% / `grids` 格(可不對稱)。
  - `PAUSE`:撤掉網格、全部賣出(例如明顯跌破)。之後再 `SET` 才恢復。
- 重設網格時只買賣「新舊網格所需持幣的差額」,不會先全部賣掉再買回。
- 強制規則:跌破區間下緣再往下 `--stop-loss`% 停損;權益單日跌 `--daily-loss-limit`%,清倉。兩者觸發後**當日(UTC)停機、不問 AI**。
- **調整頻率**:`--interval` 決定多久問一次 AI(`1m`~`1d`,預設 `1h`)。例如 `grid --interval 4h` 每 4 小時一次,
  `--interval 15m` 每 15 分鐘一次(費用約 4 倍)。網格本身的撮合頻率由 `--tick` 決定,與此無關。

### 學習(預設開啟)

不是重新訓練模型,而是把 AI 自己的成績單放進提示詞:
1. **最近結果**:每次決策附上最近 8 次決策與「到下一次決策為止」的結果(價格、權益變化、網格成交、停損事件)。
2. **每日檢討**:UTC 換日後的第一次決策前,多呼叫一次 Gemini 檢討前一天的所有決策,整理成最多 5 條心得,
   之後每次決策都附上,下次檢討時更新(失敗會在之後的決策重試,最多 3 次)。
3. **評估過程,不只看結果**:每次結果另記區間內最差 / 最好權益(`worst_equity_pct` / `best_equity_pct`),
   合約有持倉時再記距停損最近的距離(`closest_to_stop_pct`);每日檢討另附當日最低權益與最接近停損的距離。
   檢討提示詞要求把「中途大幅虧損或差點停損才賺到」視為**險勝**,不得把當時的槓桿 / 續抱寫成心得;
   心得必須在結果相反時也成立;程式執行的停損 / 追蹤停損 / 單日上限不算 AI 自己的判斷。

注意:樣本少時容易學錯,心得只是參考;停損、上限等規則仍由程式強制執行。費用約增加 30~50%
(每次決策多幾百 tokens,每天多一次檢討)。

用 `--no-learn` 關閉學習,預設狀態檔與日誌會加 `_nolearn` 後綴,可以和學習版**同時跑**來比較:
```bash
python3 -m aitrader grid               # 學習版
python3 -m aitrader grid --no-learn    # 對照組(另開一個終端機)
```
`report` 會顯示每日檢討次數與最新心得。

| 參數 | 預設 | 說明 |
|---|---|---|
| `--interval` | `1h` | 多久問一次 AI |
| `--tick` | 5 | 撮合網格的價格更新秒數(僅 `grid`) |
| `--min-confidence` | 0.6 | `SET` / `PAUSE` 的信心門檻,低於此值維持現狀 |
| `--min-spacing` | 0.5 | 最小格距 %。AI 要求的格數太多會自動減少(手續費 0.1% 時,一買一賣打平約需 0.2%) |
| `--max-range` | 15 | 區間上下緣各自最多離現價幾 %,超過會截斷 |
| `--stop-loss` | 5 | 區間下緣再往下幾 % 停損;0 = 不設 |
| `--daily-loss-limit` | 3 | 權益單日下跌達此 % 清倉,當日停機 |
| `--max-reconfigs` | 4 | 每日最多重設 / 暫停次數 |
| `--min-change` | 1 | 新舊區間上下緣都差不到此 %、且格數相同時不重設 |
| `--no-learn` | 關 | 關閉學習(見下方「學習」) |

另有 `--state`、`--journal`、`--reset`、`--max-steps`(`grid`)與 `--limit`、`--every`、`--max-calls`、`--cache-dir`(`grid-replay`),意義同上。
回放時 K 線內部走勢未知,以保守路徑(陽線先探低、陰線先拉高)撮合,成交次數會比實際少。

## 合約模式

USDT 永續合約、單向持倉、全倉保證金。**只模擬,不下真單**;槓桿會放大虧損,請先用模擬盤驗證。

- 每根 `--interval` K 線收盤後問 AI:`LONG` / `SHORT`(附目標槓桿)、`FLAT`(平倉空手)、`HOLD`(維持)。
  已有持倉時可加減倉或直接反手。**減倉與平倉不占** `--max-trades` 次數(降低風險不該被次數卡住);
  **部分減倉後停損價維持不變**(剩下的部位在同一個價格停損,虧損隨部位變小),加倉與新倉才依當下額度重新計算。
- 兩次決策之間價格往持倉不利方向走超過 `--alert-move`%(預設 1.5),或已走完到停損價距離的 `--alert-stop-progress`%(預設 50)
  時立刻多問一次 AI(急跌檢查),
  提示它可部分減倉、之後再視情況加回;回放在 K 線內部走勢經過觸發價時同樣檢查。
- 每 `--check-every` 秒(預設 30)以**標記價格**檢查強制規則,依「價格先碰到哪個」:
  - **停損**:持倉虧損達錢包 `--stop-loss`%(預設 3)平倉。
  - **追蹤停損**:獲利達錢包 `--trail-activate`%(預設 2)後啟動,從獲利高點回吐超過 `--trail-distance`%(預設 1.5)就平倉,
    最低約保本(以進場價計,未計手續費);`--trail-activate 0` 關閉。AI 每次決策看得到目前的追蹤停損價。
  - **單日虧損上限**:權益較當日(UTC)開始跌 `--daily-loss-limit`%(預設 5)或虧 `--daily-loss-amount` 金額,
    先到者為準;平倉並停到隔天、不問 AI。
  - **強平**:權益低於維持保證金(名目價值 × 0.5%)時以強平價強制平倉,另扣 0.5% 清算費。
    價格跳空越過強平價時一律以強平處理(交易所會先強平)。強平後當日停機;權益低於初始 1% 視為爆倉並結束。
- **資金費**:每次結算(通常每 8 小時)依結算前的費率收付:費率為正時多方付、空方收。
- 回放使用合約 K 線與歷史資金費率;K 線內部以保守路徑檢查停損 / 強平。
- 畫面:每次決策與強制出場後顯示持倉、今日剩餘額度與**累計成績**(成交筆數、已實現損益、手續費、資金費、報酬);
  接續時先列出累計成績與最近 5 筆成交,不必另外執行 `report`。
- 兩次決策之間每 `--status-every`(預設 `5m`,可寫 `5s` / `5m` / `1h` 或秒數,`0` 關閉,最短 5 秒)印一行狀態:
  標記價、持倉、未實現損益、權益、今日剩餘額度、下次問 AI 的時間。只顯示,不交易、不增加 AI 費用。
- **多個交易對**:`--symbol SOLUSDT,ETHUSDT,SUIUSDT`(逗號分隔,最多 8 個)。
  - `futures`:每個交易對一個子程式同時執行,帳戶、心得、新聞、狀態檔與日誌各自獨立(檔名依交易對),
    輸出每行加上 `[SOL]` 等前綴;Ctrl+C 或關閉視窗時全部存檔後結束。費用約為單一交易對 × 個數。
    已在跑的交易對(例如 SOL)不要重複放進另一個指令,會因狀態檔已被鎖住而只有那一個失敗。
  - `futures-replay`:依序回放,最後列出各交易對的報酬 / 回撤 / 成交對照表;單一交易對失敗不影響其他。
  - 多個交易對時不能指定 `--state` / `--journal`。
  - 只重設其中幾個:`--reset ETHUSDT`(逗號分隔,其他照常接續);`--reset` 不加值則全部重設。
    例如舊狀態檔的週期與這次不同而拒絕接續時,加一次 `--reset ETHUSDT` 啟動,之後同一個指令拿掉 `--reset` 即可。
  - 某個交易對啟動失敗或中途結束時,會立刻顯示「[ETH] 已結束(代碼 2);⚠ 其他交易對繼續執行」。

### 依當日剩餘額度控管倉位

「今天還能虧多少」= 目前權益 − 當日權益下限(由 `--daily-loss-limit` / `--daily-loss-amount` 決定)。每次開倉:
- 這筆的停損金額 = min(錢包 × `--stop-loss`%, 剩餘額度 × `--risk-per-trade`%(預設 50))。
- 停損距離(價格 %)= 停損金額 / 錢包 / 槓桿,且不得小於 `--min-stop-distance`(預設 0.5%,太近會被正常波動掃掉),
  所以**可開槓桿上限 = 停損 % ÷ 0.5%**,也不超過 `--max-leverage`。
- 結果:今天虧越多,下一筆能開的倉位越小;額度幾乎用完時不再開新倉(平倉不受影響)。
  AI 每次決策都會看到目前的可開槓桿上限與剩餘額度。

例:本金 30,000 元、一天最多虧 1,000 元 → 第一筆停損最多虧 500 元(1.67% 錢包)→ 可開約 2 倍(上限 2 倍);
若這筆停損了,剩 500 元額度 → 下一筆最多虧 250 元 → 可開約 1.67 倍。

### 台幣

`--currency TWD` 時,`--cash`、`--daily-loss-amount` 以台幣輸入,畫面與報表以台幣顯示。
帳戶實際仍以 USDT 計價;匯率啟動時從台灣交易所 MAX 的公開報價取得(取不到可用 `--twd-rate 32` 指定),
執行期間固定使用該匯率。實盤另有台幣換 USDT 的出入金與價差成本,模擬不計。

### 學習

和網格模式相同(見上方「學習」):每次決策附上最近 8 次決策的結果(含決策後持倉、停損 / 強平事件),
每天檢討一次並更新最多 5 條心得。`--no-learn` 關閉,預設檔名加 `_nolearn`,可與學習版同時跑比較。
`--style` 不是 `auto` 時預設檔名也加風格(如 `futures_SOLUSDT_gemini_balanced.json`),可以和 auto 版同時跑比較風格。

| 參數 | 預設 | 說明 |
|---|---|---|
| `--style` | `auto` | 交易風格:`auto` 不指定、由 AI 依證據 / 成績單 / 心得自行判斷 / `conservative` 保守(趨勢明確才進場)/ `balanced` 平衡偏積極 / `aggressive` 積極。只影響 AI 進場意願,風控不變 |
| `--max-leverage` | 2 | 槓桿上限(最多 10),AI 要求更高會被截斷 |
| `--min-confidence` | 依風格 | AI 信心低於此值不交易;未指定時 auto 0.5 / 保守 0.6 / 平衡 0.5 / 積極 0.45 |
| `--min-change` | 20 | 同方向調整的曝險差距小於此 % 不交易(100 = 1 倍) |
| `--stop-loss` | 3 | 持倉虧損達錢包此 % 平倉 |
| `--daily-loss-limit` | 5 | 權益單日下跌達此 % 平倉並停到隔天 |
| `--max-trades` | 6 | 每日最多成交筆數(不含強制出場) |
| `--fee` | 0.0005 | 單邊手續費率(合約吃單) |
| `--slippage-bps` | 2 | 滑價(基點) |
| `--cash` | 10000 | 模擬保證金,以 `--currency` 計 |
| `--currency` | `USDT` | `USDT` 或 `TWD`(輸入與顯示幣別) |
| `--twd-rate` | 即時 | USDT/TWD 匯率;不指定則從 MAX 取 |
| `--daily-loss-amount` | 0 | 單日最多虧損金額(以 `--currency` 計),與 % 先到為準;0 = 不用。金額比 `--daily-loss-limit` 寬時會被 % 蓋過,啟動時會提醒 |
| `--risk-per-trade` | 50 | 每筆停損時最多用掉當日剩餘額度的 % |
| `--min-stop-distance` | 0.5 | 停損距離(價格 %)下限,決定可開槓桿上限 |
| `--no-learn` | 關 | 關閉學習 |
| `--trail-activate` | 2 | 追蹤停損啟動門檻(獲利占錢包 %);0 = 關閉 |
| `--trail-distance` | 1.5 | 追蹤停損回吐距離(錢包 %) |
| `--alert-move` | 1.5 | **急跌檢查**:有持倉時價格自上次決策往不利方向走超過此 %,不等整點立刻多問一次 AI(可部分減倉、平倉、續抱或反手);每次例行決策後最多觸發一次;0 = 不用此條件 |
| `--alert-stop-progress` | 50 | 急跌檢查的另一個條件:價格已從上次決策價走完「到停損價距離」的此 %(槓桿高、停損近時固定 % 門檻會比停損還遠);兩個條件先到者觸發;0 = 不用 |
| `--reflect-model` | `GEMINI_REFLECT_MODEL` | 每日檢討與每日新聞用的模型(未設則與決策同一個) |
| `--news` | 關 | 每日新聞(只有模擬盤,見下方) |

### 每日新聞(`--news`)

每天(UTC)第一次決策時,用每日檢討模型 + Google 搜尋整理過去 24 小時該幣與大盤的重大消息
(摘要、偏多 / 偏空 / 中性、最多 4 則附日期與來源的事件),當天每次決策都附給 AI 當背景參考;
隔天檢討時也會一併參考前一天的消息面。

- 來源:提示詞要求優先用 Reuters、Bloomberg、CoinDesk、The Block 與官方公告,排除社群、謠言、價格預測與業配。
  Google 搜尋無法限制網域,所以程式會記錄實際引用的網站、標示主流來源(✓),並把「主流來源數 / 總數」告訴 AI;
  **沒有附上引用來源的結果一律不採用**(可能是模型憑記憶回答)。實測來源常以二線網站為主,請自行查核。
- 失敗(逾時、無來源、模型不支援搜尋)不影響交易。API 偶爾漏回引用來源,所以沒有來源時同一輪立即重試(最多 3 次);
  每天最多 2 輪(最多 6 次呼叫)。超過 36 小時的摘要不再附給 AI。
- 費用:一天多 1 次呼叫(實測 Pro 約輸入 900 / 輸出 3,400 tokens)加 Google 搜尋費用;`report` 會分開列出決策 / 檢討 / 新聞的 tokens。
- 回放無法取得當時的新聞(搜尋只會找到現在的消息,等於偷看未來),所以 `futures-replay` 不支援。
- **同一個交易對的多個帳戶共用新聞**(例如同時跑 auto 與 balanced):第一個搜到的寫入 `state/news_<SYMBOL>.json`,
  其他帳戶同一天直接採用、不再呼叫(畫面標示「共用」);另一個帳戶正在搜時最多等 4 分鐘再自己搜。搜尋失敗不寫入。

簡化與限制:維持保證金率固定(實際依倉位級距調整)、不模擬委託簿深度與插針;資金費以結算前最後看到的預估費率計算,
程式停機期間錯過的結算不計。

## 運作方式(目標持倉模式)

每個決策點:
1. **強制風控**:單日虧損上限、停損、停利。觸發就直接清倉,**不問 AI**。
2. **問 AI**:送出技術指標(報酬率、均線、MACD、RSI、ATR、波動度、區間位置、量能、最近 24 根收盤)與目前持倉;Gemini 以固定 JSON 格式回覆 `action`(BUY/SELL/HOLD)、`target_position_pct`、`confidence`、`reason`。
3. **驗證輸出**:格式不符、數值超出範圍、被安全機制擋下、API 錯誤 → 一律視為「不交易」並記錄。金鑰錯誤 / 模型不存在等設定錯誤會直接停止並提示。
4. **風控過濾**:信心門檻、持倉上限、最小調整幅度、每日交易次數。
5. **模擬成交**:市價成交,計入手續費與滑價;寫入決策日誌。

## 儀表板(瀏覽器檢視)

```bash
python3 -m aitrader dashboard            # 開 http://localhost:8765(預設台幣;--currency USDT 改 USDT)
```
或在模擬盤指令加 `--dashboard`(預設 port 8765)順便開啟,不用另開分頁;同時跑多組時只要其中一組加,
另一組也加的話會提示 port 已被使用、不影響交易。

- 自動找出 `state/` 裡所有合約模擬盤帳戶,**預設只顯示執行中的**(停掉的幣種、沒開的風格按「含已停止」才顯示)。
  各風格合計以執行中的帳戶為主,另列「含已停止」(例如停掉的 ETH 凍結時的損益);已停止且從未成交的帳戶不算入合計。
- 內容:各風格合計、每個帳戶的權益 / 持倉 / 停損價與距離 / 追蹤停利、權益曲線(金額或 %)、
  各交易對 K 線(含成交量、成交標記與持倉的進場 / 停損 / 追蹤停利線,可拖曳縮放)、風格對照表(報酬、最大回撤、平倉勝率、手續費)、
  最近 40 筆決策與理由、心得與當日新聞(含來源)、近 24 小時 AI 用量。帳戶資料每 15 秒更新;
  **現價與 K 線每 3 秒更新**(價格變動時閃綠 / 紅,標題旁顯示幾秒前更新),K 線可切換 1m / 5m / 15m / 1h(記住選擇),
  最後一根是正在形成的(只供顯示;AI 決策仍只看已收盤的 K 線),更新時只改最後幾根,拖曳 / 縮放的畫面不會跳。
- 只讀不寫、預設只綁 127.0.0.1;圖表程式庫(Chart.js、TradingView Lightweight Charts)從 CDN 載入,沒網路時只顯示表格。
- 追蹤停利價以預設的 `--trail-distance` 估算;執行中的帳戶以即時標記價格計算權益。

## 長時間執行(避免電腦睡眠)

模擬盤要一直執行才有意義:電腦睡眠時不會檢查停損、不會問 AI,醒來才用當下價格處理,成績會失真
(實盤更危險:倉位留在交易所無人看管)。macOS 建議:
```bash
caffeinate -s python3 -m aitrader futures ...   # 接電源時防止系統睡眠;筆電上蓋不能闔上
```
程式會偵測中斷:兩輪之間(或接續時距上次存檔)超過 10 分鐘,畫面顯示「偵測到程式中斷 N 小時」並寫入日誌,
`report` 會統計中斷次數與總時數(`grid` / `futures`)。

## 重要限制
- **AI 沒有被證明能穩定獲利。** 請先用 `replay --model rule` 當對照組,並讓 `paper` 跑一段時間再評估。
- **回放結果偏樂觀**:如果回放期間早於模型訓練資料的截止日,模型可能「記得」當時行情。模擬盤(即時)結果才可信。
- 不模擬委託簿深度與部分成交;停損只在檢查點觸發(回放每根 K 線、模擬盤每 `--check-every` 秒),實際可能成交在更差的價格。
- 費用:模擬盤每根 K 線呼叫一次(1h 週期約每天 24 次);回放用 `--every`、`--max-calls` 與快取控制呼叫次數。
